# Сюжет: хто за що відповідає

Розділ карти `docs/ARCHITECTURE.md`: правила й «Перед словом «готово»» там, збірка й робочий цикл у `docs/jobs/build.md`, тут лише таблиці цієї частини моду. Кожен рядок: що потрібно → єдине місце в ядрі → чого не робити поруч із ним. Як воно працює (слова даних, пороги, порядок), каже шапка названого файлу чи коментар біля названого члена: рядок тут лише веде туди. Писати дані сюжету й сцени: `docs/jobs/story-data.md`, `docs/jobs/scene.md`.

**Що `storycheck` бачить у кроках.** Аргументи кроків і слова умов перевіряє сама гра при завантаженні (у лог і у VERDICT перевірки сцени). Перші слова кроків сцени `storycheck` звіряє з кодом. Крок із власними словами після аргументу оголошує їх у своєму модулі, і `Read` бере їх звідти ж: `const string XStep = "prop take"`, `XFlags = { … }, XValued = { … }` (`StoryProps`). Тоді `storycheck` зупиняє одруківку в цих словах (і в людини: `npc <хто> prop take …`); предмет `RavenWatch_item_<id>` має бути в `assets/items` чи `assets/story/items`. Свої числа речі у файлі предмета (`hang:`, `lies:`, `falls:`) `storycheck` звіряє зі списками `StoryProps.HangWords`, `LiesWords`, `FallsWords`: невідоме слово чи слово без числа зупиняє збірку.
