# Світ, мережа, сумісність: хто за що відповідає

Розділ карти `docs/ARCHITECTURE.md`: правила й «Перед словом «готово»» там, збірка й робочий цикл у `docs/jobs/build.md`, тут лише таблиці цієї частини моду. Кожен рядок: що потрібно → єдине місце в ядрі → чого не робити поруч із ним. Шапка названого файлу каже, як воно працює.

## Що відбувається у світі

| Що потрібно | Єдине місце | Не роби |
|---|---|---|
| Що довкола гравця (вороги, дах, корабель) | `Senses` (один збір для всіх) | власні сканування сцени |
| Чи може ворон сам злетіти з плеча (сором'язливий, до Одіна, прогулянка, гра зі звіром) | дві брами: `Trust.FreeToLeave` (на хвилини) і `Outing.CanGo` (коротко); обидві питають `Senses`: не в бою, не під дахом, не під землею, не в сцені сюжету (`Senses.InScene`, ставить `StoryModules`; прогулянку сцена кличе назад — користувач 2026-11-16) | свою перевірку «чи можна злетіти» в модулі, що відпускає ворона |
| Подія сталася | `Diary` для воронів, `StoryBus` для сюжету. Гравець збудував річ: один хук `Diary.Placed` (що, сама деталь, «cheated»), він сам каже всім, кому треба | нова власна шина; ще один патч на `PlacePiece` |
| Доручення | `Errands`; новий вид кроку в реєстрі `ErrandSteps` | нові гілки в ядрі доручень |
| Ефекти | `FxLib`, `RavenFx` (видимі всім поруч) | свій спавн ефектів без мережі |
| Зникнення чогось | `Fades` | щоб зникало миттєво |
| Чи це дика рослина чи камінь світу, а не чиясь річ (прибрати з-під місця сюжету, з коріння дерева воронів) | `Wild.Is(zdo\|view)`: вид за префабом (`Wild.Kind`: дерево, колода, камінь, те, що ламається чи збирається, звичайний кущ гри, що має лише `StaticPhysics`; не істота, не предмет, не деталь, що зношується) і ніхто її не ставив (творця нема). `Piece` на префабі нічого не каже: PlantEverything робить деталями самі кущі гри, щоб їх можна було саджати. Перевірка `wild-core` | свій список компонентів «росте» в модулі; `GetComponent<Piece>() == null` як «дике» |
| Нагорода за бій, де можуть битися інші (бос, ватажок завдання, набіг) | Стояти поруч мало, потрібен власний удар гравця чи його ворона: бос — `Strike.YouStruck`, ватажок — `Champions.OwnerStruck` (ключ у ZDO, бо лут вирішує гра, що веде ватажка), набіг — `Senses.HitMonsterAt` | рахувати лише відстань до місця бою |

## Сумісність і мережа

| Що потрібно | Єдине місце | Не роби |
|---|---|---|
| Дані на гравці | `NetFlag.Zdo` (RavenFx.cs) | свої способи |
| Прибрати значення з ZDO | запис, який отримає кожна гра: порожній рядок, нуль чи позначка «нема»; значення людини, що живе в шафці, — `NpcLocker.Put` (позначку ставить `NpcLocker.Off`). Правило `zdo-remove` | видалення ключа гри (RemoveString, RemoveInt…): воно не шлеться, і на сервері та інших іграх лишається старе значення, яке потім повертається |
| Патч на код істот, бою, ШІ, спорядження гри | обгортка `try` + `PatchGuard.Fail` | патч без захисту: він ламає метод гри |
| Гру оновили: що дивитись першим | `node tools/patchmap.js`: класи гри, які мод патчить, від найбільш латаного; `<Клас>` — його методи й наші файли; `--fragile` — приватні поля й методи гри, названі рядком чи параметром `___поле`. Чи патчений метод ще існує, каже `patchcheck` при збиранні; перейменоване приватне поле не ловить ніщо, воно ламається мовчки | список патчів у документі: він застаріває; вважати зелений `patchcheck` доказом, що після оновлення гри все ціле |
| Інші моди | мод працює на чистій грі, залежності м'які. Читай чужий код лише щоб зрозуміти | копіювати чужий код |
| Камера іншого мода стоїть біля людини (фон за лялькою на аркуші PoV: 0,6 м перед очима гравця) | `NpcForeignCamera`: поки відкрита торба, людина ближче `Near` до будь-якої камери, крім камери гри, не малюється лише на час цього кадру тієї камери (`forceRenderingOff`); за назвою мода нічого не шукаємо. Наша камера, якій не можна бачити одну людину (другий манекен на аркуші дубля), каже це тут же: `NpcForeignCamera.Away` | патч на камеру чи вікно конкретного мода; ховати людину для всіх камер |
| Вікно скрині чи сумки, хоч би хто його малював | `FeederUi.WindowOf`: іти вгору від сітки гри, поки друга сітка лишається зовні. Мод інтерфейсу носить сітку гри у своєму вікні, тож назва мода не потрібна; на чистій грі це панель гри | шукати чуже вікно за назвою класу |
| Ворон у чужій могилі | `GraveRavens.Keeps` на дверях `Inventory.AddItem`: будь-яке «взяти все» спершу додає, потім прибирає, тож відмова лишає ворона в могилі | свій патч на «взяти все» кожного мода |
| Назвати інший мод інтерфейсу в коді | ніколи: автоматична перевірка Thunderstore зачепилась саме за це (2.9.0). Правило `no-ui-mod-names` | рефлексія чи патч на чужий мод інтерфейсу |
| Шукати об'єкт гри | брати оригінал гри, а не копію іншого мода | |
| Заборонити E на речі (деталь місця: підставка, замкнена скриня) | на E самого гравця: `LocInteractPatch` (LocPatches.cs) (`Player.Interact`, `Priority.First`), а не на `Interact` самої речі: Harmony виконує всі префікси, хоч би що сказав наш, тож префікс іншого мода на речі (ZenItemStands, MultiUserChest) відкривав її повз заборону. Порожня підказка — постфікс `Priority.Last`, щоб чужий не писав поверх. Схована деталь вимикає й те, що створює пізніше (річ на підставці: `LocState.StandMade`), разом із колайдерами | заборона префіксом на `ItemStand.Interact` чи `Container.Interact`; ховати лише малювання |
| Тихе місце в дикій природі (далеко від баз, відкрито) | `WorldSpot.Pick` (схованка ворона, своя точка сюжету), `WorldSpot.Open` (місце світу для сюжету); чи дійти туди суходолом — `WorldSpot.DryWay` (один для всіх: і хто приходить пішки, `NpcTravel.ComeFrom`) | свій пошук місця; своя перевірка «через воду» |
