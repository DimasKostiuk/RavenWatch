# Інструменти автора: хто за що відповідає

Розділ карти `docs/ARCHITECTURE.md`: правила й «Перед словом «готово»» там, збірка й робочий цикл у `docs/jobs/build.md`, тут лише таблиці цієї частини моду. Кожен рядок: що потрібно → єдине місце в ядрі → чого не робити поруч із ним. Як воно працює (правила, команди, що лягає у звіт), каже шапка названого файлу: рядок тут лише веде туди. Зробити кліп чи сцену: `docs/jobs/clip.md`, `docs/jobs/scene.md`.

Яку помилку що вже ловить (ядро, `clipcheck`, VERDICT): `docs/arch/tools-catches.md`. Це довідка, цілою її не читають: перед новим правилом перевірки чи новим уроком знайди там свою помилку.

## Інструменти автора

| Що потрібно | Єдине місце | Не роби |
|---|---|---|
| Перевірити позу тіла (палець, долоня, кулак, рука в тілі, лікоть, коліно, ковзання ноги, різкість, промах, реквізит, хват, дотик) | `BodyCheck`: єдиний набір правил для манекена (`raven stage check`) і для сцени (`StudioScene.cs`). Рядок VERDICT має тег правила й, де ядро може порахувати, команду `fix: node tools/anim.js …` (`BodyCheck.FixLine`, `WholeOf`, `KeyNear`). Через прийнятий кліп нічого не ховається й не послаблюється: `anim.js approved` дає список користувачу. Стрілки на близьких кадрах: `BodyCheck.Marks` → `Studio.Mark`. В інструментах лише своє: чи стояв манекен, стики частин; кадр і мигання в сцені | свої перевірки пози в кожному інструменті; числа для правки в чаті замість `fix:` у звіті |
| Звіт дубля | `AnimStage.Report`: `stage_<кліп>.txt` короткий і `stage_<кліп>.full.txt`; у заголовку хеш файлу кліпу (`AnimStage.Hash`), `anim.js` звіряє його з файлом. Короткий каже кожну річ один раз: VERDICT — рядок на подію, за часом події, з кількістю (`BodyCheck.Fold`: ривки кісток хвостом рядка польоту лише своєї кінцівки — кістка руки під політ тієї кисті, ноги під політ тієї ступні (`BodyCheck.LimbOf`, `BodyCheck.JerkWith`), чужа лишається рядком; ліва й права кінцівка однієї миті одним рядком, кожен `fix:` один раз; те саме згортання у звіті сцени, `StudioScene.cs`, де подія не йде через межу кроку); пози кадрів — перша повна, далі «Δ» і лише частини, що змінились проти востаннє сказаного, «= no change» без номера кадру (`BodyCheck.Differs`, межі `BodyCheck.SameDeg`, `BodyCheck.SameM`); рядок контрольного аркуша — час, тег і предмет рядка (`BodyCheck.Subject`), види, «Δ frame N» (`AnimStage.PoseNear`). Повний нічого не згортає: VERDICT рядок на правило й кістку, кожна поза ціла | читати звіт, не знаючи, від якої версії файлу він; своє згортання чи скорочення в інструменті: нове правило — у `BodyCheck.Fold`; шукати в короткому звіті число, яке згорнуто: воно в повному |
| Побачити дубль з одного файлу | контрольний аркуш `stage_<кліп>_key.png` (`AnimStage.KeyMoments`, `KeyViews`, `Studio.StageKey`, `Studio.Label`, `Studio.Text`); «було / стало» `stage_<кліп>_diff.png` (`AnimStage.OtherFor`); аркуші всього прогону лише на запит (`anim.js views`); у сцені підпис кроку на кадрі й великі кадри початку кроків (`StudioScene.cs`, `StepFrame`) | десять аркушів на дубль; судити з кадру без підпису, коли він |
| Сказане користувачем про кліп | рядки кліпу `say` (його слова) і `want <час> …` (ті слова мірою; словник у `BodyCheck`). Новий кліп без `say` зупиняє `clipcheck` | лишати його слова лише в чаті |
| Чого торкається кліп | рядок `touch wall 0.55` / `touch piece stave_gate 0.55` (слова пристосування): манекен ставить його сам, перевірка сцени міряє променем справжню поверхню | писати відстань лише в коментарі |
| Кліп рухами, не ключами | `tools/motion.js` (`anim.js do`, шапка каже кожен рух): сценарій рухів живе в шапці кліпу рядками `# do …`, ключі каналів зі списку `# scripted:` робляться з нього знову при кожній зміні (`regen`), решту тіла за руками дораховує один прохід (`accompany`, `# alive`); прогноз з ключів до дубля (`predict`), дзеркало (`mirror`). Межі читає з `src/BodyCheck.cs`. Канал, узятий руками (`set`, `move`…), сценарій не чіпає | другий генератор ключів поруч; правила «живе тіло», «замах», «ступня згори» текстом замість руху; копія меж `BodyCheck` у інструменті |
| Кліп чи сцена ззовні гри: один вхід | `node tools/anim.js <дієслово>` (`tools/anim.js`, шапка каже кожне): правки кліпу — `tools/clip.js` (перевірка `clipcheck`, відмова відкочує), рухи — `tools/motion.js`, дублі, `fix` (команди звіту як є), порівняння з дублем перед цим, сцени, `approved`, `status` — `tools/take.js`. Шлях студії в `tools/studio.path`. Слова `raven stage …` і `studio/request.txt` лишаються знизу | ручні скрипти в тимчасових теках; `raven stage` і `request.txt` у документах для моделі |
| Те, чого торкається тіло на манекені (стіна, стіл, сидіння, сходинка, точка, деталь гри) | `AnimStageFixtures.cs`: коробка в системі тіла, `BodyCheck` міряє дотик | ставити тестові речі в світ |
| Яка поза вже є | `docs/CLIPS.md` (кожен кліп: що показує, тіло, від → до, частини, до чого торкається, де вжито, стан), `anim.js find`; `clipcheck` зупиняє кліп без рядка | робити позу, не пошукавши схожу |
| Перевірити сцену | студія `scene <назва> <сцена> [fps] [з рядка]` (`StudioScene.cs`); світ прогону ставлять рядки сцени `check:`, `test:`, `npc <хто> at <місце>`, після прогону все повертається. Таблиця кроків із результатом кожного: `StoryScenes.Outcomes` (`EndStep`, поле `Done` у `StepKind`, хода гравця `StoryWalk.Outcome`). Перед словом «готово» про сцену — цей прогін і погляд на кадри | показувати сцену користувачу неперевіреною |
| Перевірити сцену без гри | `node tools/anim.js scene --dry <сцена>` (`tools/scene_dry.js`): таблиця кроків і попередження з самого файлу (кадр довше `StepLong`, людина без `test: npc … at`, слова над птахом у польоті; про кадри: надто короткий, стик двох однакових, довга розмова під одним, перетин лінії, обрізаний наїзд); `scene --cover <сцена>` пропонує кадри розмови й нічого не пише; слова й місця — `storycheck` на цю сцену | рахувати час сцени в голові; запускати гру, щоб побачити одруківку |
| Тіло смикається: хто винен | `raven jolt on`, побачив — Num1, `raven jolt report` (`JoltWatch`: тіло читається в сімох точках кадру); `raven jolt mute clips\|gait\|turn` вимикає шар людини для порівняння | здогадки; `NpcPoseWatch` для цього: він бачить лише кістки людей у кінці кадру |
| Тестові інструменти | шаблони NPC лише для автора — назва файлу з `_` на початку (`assets/story/npc/_dummy.txt` манекен, `_test_*`): у мод не йдуть (`StoryFiles`, `rw_build`), сюжет їх назвати не може (`storycheck`); вікно `DevPanel`, `Studio`; команди тесту сюжету кнопками: вкладка «Тест» (`StoryPanelTest.cs`: рядок консолі — одна кнопка) | окреме вікно для кожної дрібниці |
| Нова модель | Майстерня → файл моделі; `assets/fbx`, `assets/story/fbx` | ручне створення об'єктів у коді |
| Фарби й речі ворона наживо | `LooksPanel`: вкладка «Фарби» тестового вікна — вигляди (`RavenLooks`) на власній сцені; «Зберегти» пише `config/RavenWatch/looks/<id>.txt` | правити вигляд числами в коді |
