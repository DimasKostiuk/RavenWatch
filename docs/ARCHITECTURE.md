# RavenWatch: архітектура всього моду

Прочитай це перед будь-якою зміною коду моду.

**Головне правило: спершу знайди місце в ядрі.** Майже кожна велика частина моду вже має одне місце, через яке проходить уся її робота. Якщо поведінка неправильна, виправляй її там, де вона народжується. Не додавай поруч другий механізм, таймер, менеджер чи «рятівника». Те, що нова система замінює, видаляй, а не лишай поруч.

Якщо ядро справді не вміє потрібного: розшир ядро або скажи користувачу, чого бракує, і запропонуй варіанти. Обхід мовчки не роби.

**Друге головне правило: без зайвих важких викликів.** Там, де важкий виклик справді потрібен, він дозволений, але має бути прогнозованим і якомога легшим: заздалегідь відомо, коли він спрацює, як часто і скільки роботи зробить.

Шапка кожного файлу пояснює його роботу, тож прочитай її, перш ніж чіпати файл. Нижче вказано, куди дивитися насамперед.

## Хто за що відповідає

### Ворон: тіло й рух

| Що потрібно | Єдине місце | Не роби |
|---|---|---|
| Будь-який політ ворона | `RavenFlight` (`FlightBody`), `RavenMotor` (`Motor.cs`), плани в `FlightPlans` | власний шлях польоту |
| Хто зараз керує вороном | `AnimDirector.Take` / `Release`: сильніша дія забирає птаха у слабшої | рухати птаха, не взявши його |
| Анімація ворона | наші кліпи й ключі крил | кліпи ворони, чайки, валькірії |
| Ворон на плечі | `Shoulder` (малювання за даними гравця), `RavenSeat` (місце), `ShoulderLife` (життя) | слот гри для ворона |
| Сидіння ворона на жердині | `Perches`, `PerchView`, `PerchLife` | окремі місця для кожної будови |
| Голова ворона | Одна межа на всього птаха: `RavenHead.YawMost` (85°), кожен поворот голови йде через `RavenHead.Limit`: сидіння, плече, кивок, зліт, політ, `Saccade`. Менша за 90°, бо рух іде коротшим шляхом і за 90° він проходить через спину | свій поворот голови повз `Limit`; межа понад 90° (перевірка `raven-head` зупиняє збірку) |
| Сюжетний ворон і ворон NPC | `StoryBird` (картинка без мережевого об'єкта), `NpcRaven` | ще один тип птаха |

|---|---|---|

| Довгий фон під сценою | `Audio.Bed` | свій цикл |
| Решта світу тихше | `Audio.Mix`: `world` (`SfxVol`, значення гравця повертається), `ambient` (вітер, море, фон), `music`, `voice`; кілька власників — діє найтихіший | писати в мікшер напряму |

| Звільнити все | `Audio.End(власник, с, обірвано)`: один виклик; сцена робить це в `StoryAudio.SceneEnd` | прибирати звук частинами |
| Слова сцени | `music`, `bed`, `mix`, `mute`, `unmute`, `ear`, `sound`: `StoryAudio` (шапка) | |
| Що зараз звучить | `raven audio`, кожна зміна в лозі з префіксом `Audio:` | |

### Інтерфейс і налаштування

| Що потрібно | Єдине місце | Не роби |
|---|---|---|
| Книга воронів | `RavenBook*`; текст із підказкою золотий і з великої літери, без «?» | другий вид вікна |
| Скільки коштує сторінка книги | рядок `Book of ravens drawn` у лозі при закритті книги: кожна вкладка, побудова, розкладка, наступний кадр, що створилось при кліку (`BookArt.Late`). Форма чи картинка створюється раз і лежить у `BookArt`; дорога — здешев її там | готувати заздалегідь те, що можна зробити дешевим; своє кешування поза `BookArt` |
| Чи вміє гравець говорити з вороном | `RavenBook.Given`: у сюжетній збірці книгу дає хата Ейріка (дія `book`), без неї ворон лише сидить; клавіші, коло, голод (`Satiety.Draining`), смерть, прохання питають лише її. Хто мав ворона до сюжету, отримує книгу одразу. Без книги Провідник приносить лише теми `Bookless` (люди, `NoBook`); ворон від Гальдора без книги: тема `NoBook` одразу, а пролог скорочує свої паузи (умова `book`, розвилки `ownraven any, !book`) | свій замок у підсистемі |
| Клавіші | Свої клавіші моду: `RavenKeys`. Лише слухають, у гри й інших модів нічого не забирають. Стан кнопок гри (стрибок, присід) читай напряму через `ZInput` | перехоплювати клавішу |
| Коло дарів і наказів | `RavenRadial`, `OrdersMenu` | своє меню |
| Налаштування | ~35 головних у меню, решта в `tuning.cfg`. Баланс сервера іде через `ServerConfig` | новий рядок у меню без потреби |
| Ключі `Config.Bind` | без `= \n \t \ " ' [ ]`: один поганий ключ вбиває весь мод | |
| Консоль | `raven` у `Commands`, англійські слова; лише адмін, крім `raven book` | |
| Перевірити позу тіла (палець прямий, долоня, кулак, рука в тілі, лікоть, коліно, плече, шия, ковзання ноги, різкість, промах, реквізит, хват реквізиту, дотик) | `BodyCheck`: єдиний набір правил для манекена (`raven stage check`) і для сцени (`StudioScene`). У самих інструментах лише своє: чи стояв манекен, чи стикуються частини; кадр і мигання в сцені | свої перевірки пози в кожному інструменті |
| Сказане користувачем про кліп | рядки кліпу `say` (його слова) і `want <час> …` (ті слова мірою; словник у `BodyCheck`): `check` пише, що з проханого вийшло. Новий кліп без `say` зупиняє `clipcheck` | лишати його слова лише в чаті |
| Чого торкається кліп | рядок `touch wall 0.55` / `touch piece stave_gate 0.55` (слова пристосування): манекен ставить його сам, перевірка сцени міряє променем справжню поверхню | писати відстань лише в коментарі |
| Один прогін кліпу чи сцени ззовні | `node tools/take.js clip|scene|approved`; `approved` порівнює прийняті кліпи зі збереженими числами після зміни ядра | ручні скрипти в тимчасових теках |

| Перевірити сцену | студія `scene <назва> <сцена> [fps] [з рядка]` (`StudioScene`), рядок сцени `check: <місце[.річ]> <м> [in]` каже, де гравець її починає (інакше перевірка ставить у середину місця); `test: <дії сюжету; …>` і `npc <хто> at <місце>` (поруч, одразу) ставлять світ, у якому вона грає, а все, що прогін змінив (ключі сюжету світу, сюжет персонажа, де стояв гравець), повертається після нього; гравець за клавішами під час прогону — у VERDICT: сцена грає, кожне тіло міряється щокадру правилами `BodyCheck` (ще кілька секунд після кінця), плюс кадр: мигання, поза кадром, щось заступає, камера в чомусь, HUD; кадри з камери сцени, близькі кадри кожного тіла, поза словами на кожному кроці й VERDICT. Перед словом «готово» про сцену — цей прогін і погляд на кадри | показувати сцену користувачу неперевіреною |
| Тіло смикається: хто винен | `raven jolt on`, побачив — Num1, `raven jolt report` (`JoltWatch`): кожне тіло, гравець теж, читається в сімох точках кадру, тож видно, яка частина кадру зламала рух, а також довгий кадр, GC і кадр без кроку фізики; `raven jolt mute clips\|gait\|turn` вимикає шар людини для порівняння. Вимкнений не існує в грі | здогадки; `NpcPoseWatch` для цього: він бачить лише кістки людей у кінці кадру |
| Тестові інструменти | шаблони NPC лише для автора — назва файлу з `_` на початку (`assets/story/npc/_dummy.txt` манекен, `_test_*`): читаються на його машині, у мод не йдуть (`StoryFiles`, `rw_build`), сюжет їх назвати не може (`storycheck`); вікно `DevPanel`, `Studio`; команди тесту сюжету кнопками: вкладка «Тест» вікна сюжету (`StoryPanelTest`: рядок консолі — одна кнопка) | окреме вікно для кожної дрібниці |
| Нова модель | Майстерня → файл моделі; `assets/fbx`, `assets/story/fbx` | ручне створення об'єктів у коді |

### Сумісність і мережа

| Що потрібно | Єдине місце | Не роби |
|---|---|---|
| Дані на гравці | `NetFlag.Zdo` | свої способи |
| Патч на код істот, бою, ШІ, спорядження гри | обгортка `try` + `PatchGuard.Fail` | патч без захисту: він ламає метод гри |
| Інші моди | мод працює на чистій грі, залежності м'які. Читай чужий код лише щоб зрозуміти | копіювати чужий код |
| Шукати об'єкт гри | брати оригінал гри, а не копію іншого мода | |
| Тихе місце в дикій природі (далеко від баз, відкрито) | `WorldSpot.Pick` (схованка ворона, своя точка сюжету) | свій пошук місця |

### NPC

| Що потрібно | Єдине місце | Не роби |
|---|---|---|
| NPC іде кудись | `NpcMind.Move` → `NpcWalk.Step` → `NpcMind.Steer` | ігровий `MoveTo` / `MoveTowards`: на повороті понад 10° NPC зупиняється |
| Повне життя лише біля гравця | `NpcClock.Seen(людина)`: гравець ближче `Near` (40 м), гасне за `NearOut` (50 м), дивиться раз на секунду; `NpcClock.Slow`: у скільки разів рідше перевірки, коли не бачить ніхто (2,5 і 5). Поза, кліпи місць, частота прогулянок, запити шляху й погляд уперед питають це. Що малює саме ця гра (`BodyGait`, `BodyTurn`, ворон NPC), міряє від своєї камери. Стрибок тіла: окреме правило безпеки `NpcWalk.Watched` | свій `GetClosestPlayer` і своя відстань у модулі для «ніхто не бачить» |
| Шлях тримається далі від країв | `NpcWalkRoom` | правки шляху у викликах |
| Острів на карті шляхів (поміст, верхній поверх, сходи) | `NpcWalkLinks`: де хода зустріла розрив, а тіло пройде пряму між краями (земля кожні `LinkStep` м, сходинка не більше `StepRise`, місце для тіла), стає містком карти (`NavMesh.AddLink`, лише для нашого ходока, `LinkKeep` с); `raven npc walk report` — скільки | телепорт через острів; правити карту гри для її істот |
| Запитати шлях | хода: `NpcWalk.Ask` (усі разом не більше `AsksAFrame` за кадр, решта наступного кадру); будь-що інше — `NpcWalk.Have` (чи є весь шлях) і `NpcWalk.Way` (сам шлях): відповідь тримається `Keep` с для тих самих двох місць, рахується в `raven npc perf` («path», «path over»). | Деталі місця сюжету й люди | `NpcBase`: місце сюжету належить лише базі, що стоїть у ньому (`Loc.Holds(Centre)`): серце поруч не отримує його лав, скринь, станків; чого не тримає місце (`Loc.Keeps`) і чого нема в його стані (`LocState.Absent`, за шаром, зміна стану: `LookVersion`) — нічиє; `wears` без деталей місць. `spot:` автора йдуть повз це, але теж питають `Absent` | шукати сидіння чи скриню повз `NpcBase`/`NpcMind.Free`; патч лише на клік гравця як «замок» для людей |
| Люди сюжету у світі | `StoryPeople` (`assets/story/people`): сервер тримає кожного рівно одного; `after: <умови світу>` — до того його у світі нема; дім — перший рядок `live: … when <умови світу>`, що справджується (останній без `when` — інакше); що він робить від сюжету — команда, рядок нижче | свій спавн сюжетної людини; таймер «з'явись» у квесті; дім за станом Зали в коді |
| Команда сюжету людині | `StoryHold`: `npc <хто> hold <місце> [by <місце>] [then <місце> [by <місце>]]… [every <с>] [here] [stand\|clip <кліп> [from <кліп>] [out <кліп>]\|emote <жест>]` (квест, у сцені через `do`). Кілька місць по черзі: яке зараз, каже годинник світу, тому всі ігри й зміна господаря бачать те саме; `out` — вихід кліпу перед переходом. Чи людина в кліпі: умова `npcclip <хто> <кліп>`. «Біля речі» — це на крок від її краю з того боку, звідки людина йде (`StoryWhere.Approach`), а не в її середині. Діє, поки не `npc <хто> free` чи нова команда: кінець сцени, перезапуск, зміна господаря їй не заважають, тіла може ще не бути (ключ світу). Сцена бере людину поверх і після кінця лишає цій команді: кліп команди просить знову. `do npc <хто> free` у сцені, що тримає людину, знімає лише команду, сцена тримає її до кінця. Кліп, що вже на тілі, не починається спочатку (новий строк без стрибка). `here`: кліп ні до чого не торкається (руки складені): не підходить упритул, не дивиться на річ. Кліп сцени, що є кліпом цієї команди, після сцени лишається на тілі (`NpcMind.KeepClip`); нова команда знімає кліп через його `out` | свій таймер «повернись»; `free` наприкінці сцени, якщо людина має лишитись |
| Власне життя людини сюжету між командами | `StoryLife`: рядки `spot: <набір> <місце> [by <місце>] <вид> [sit] [clip <кліп> [from <кліп>] [out <кліп>]] [hours а-б] [stay а-б] [want н]` у `assets/story/people`; який набір зараз: `npc <хто> live <набір>` (ключ світу, без слова `home`). Той самий вибір і той самий візит, що в `NpcPlaces`, лише місця авторські; місце враховується, поки стоїть біля її дому; жодне не підходить — місця її бази. `hold` і сцена йдуть поверх | третій спосіб руху людини сюжету; квест, що щогодини пересуває її командами |
| Сюжетна людина під захистом | шаблон `unseen: yes` (`NpcVitals.Unseen`): жоден звір її не бачить і вона нічия не ворог, і вона не отримує шкоди, навіть коли живе на базі (`NpcModules`: Unhurt); без `mortal` її не поранити | свій патч на вороже ставлення |
| Свій ворон гравця в сцені | `own` (лише тому, хто воронів не має), `raven <вид> sit <місце>` і `back` (через жердини, як наказ) | рухати ворона повз `Perches` |

## Правила для всього моду

- **Плавно за замовчуванням.** Ворон, NPC, вогонь, ефекти з'являються і зникають поступово. Політ і хода без різких зупинок і телепортів, обмеження лише плавні.
- **Мережа.** Хто керує об'єктом, той вирішує й пише в ZDO лише за зміни. Інші малюють за цими даними. Те, що має пережити зміну власника чи перезапуск, зберігай у ZDO чи предметі, а не в полі класу.
- **Легка людина в мережі.** ZDO людини гра шле цілим щоразу, коли в ньому щось міняється, а в людини, що йде, позиція міняється щокадру. Тому на самій людині лише те, що кожна гра має бачити тієї ж миті (вигляд, поза, кліп, сидіння, ім'я, хто з нею говорить, її серце). Решта її значень живе в шафці: `NpcLocker.Lives`, читання `NpcLocker.Text/Num/Int/Long/Vec/Flag/Ref/HasRef`, запис `NpcLocker.Put/PutRef`. Новий ключ людини зупиняє `tools/npcnetcheck.js`, поки не вирішиш, де він живе (`tools/npcnet_keys.json`). Перевірка ваги: `raven npc net <хто>`. Причина: тест удвох 2026-11-05, 25 людей по 1–1,5 КБ не пускали базу до другого гравця. Черга важить більше за вагу: гра шле ZDO типу `Prioritized` чужого власника раніше за все, скільки б не чекало решта (`ZDOMan.ServerSendCompare`), а тіло, скопійоване з гравця, такий тип і мало (заміряно). Тому тіло людини має тип `Default` (`Npcs.BuildHuman`), тип видно в `raven npc net`; не повертай його.
- **Важкі виклики** (пошук по сцені, обхід усіх істот, фізика на область, `GetComponentsInChildren`, створення об'єктів, файли; перевірка рахує лише перші чотири, решту стеж сам):
  1. Спершу візьми готове: `Senses`, `NpcCensus`, `NpcFoes`, збережений результат.
  2. Запускай за подією, а не щокадру. Якщо треба опитувати, то рідким таймером.
  3. Не роби все в один кадр: розподіляй роботу між кадрами й обмежуй її кількість за кадр.
  4. Невдалу спробу не повторюй одразу: зроби паузу.
  5. Де виклик потрібен, напиши в його рядку, коли і як часто він спрацьовує: `// heavy: раз при завантаженні`.
  6. Заміряй «до» і «після»: `Perf` для воронів, `NpcPerf` для людей.
- **Постійні зв'язки.** ZDOID змінюється при кожному завантаженні світу, тому збережений `user:id` після перезапуску нікуди не веде. Зберігай через `NpcKit.Save` / `Resolve`. Якщо значення живе лише одну сесію, напиши `// session: чому`. З тієї ж причини зерно для всього, з чого складається NPC, бери лише з `NpcKit.Seed` (перевірка `npc-seed` зупиняє `m_uid` як зерно).
- **Помилки не ховай.** `catch` записує причину в лог. Якщо мовчання тут правильне, напиши `// quiet: чому`. Обгортка навколо незнайденої причини не є виправленням. Перевірку на `null` роби один раз на вході, а не в кожному шарі.
- **Нове для гравця (механіка, нагорода, модифікатор):** спершу покажи варіанти й перевір, чи цього ще немає в коді.
- **Коли щось не працює:** знайди справжню причину й поясни її. Не змінюй наосліп кілька разів поспіль.
- **Прибирай за собою:** зайвий код, тестові файли, знімки студії.
- **Документи для гравців:** CHANGELOG короткий, без чисел і нутрощів; у README немає команд консолі.
- **Шляхи й збирання:** `tools/rw_build.ps1`; збирати лише поточну версію; перед збиранням подивись `releases/`.

## Перед словом «готово»

Кожне питання взяте з помилки, яка вже траплялася:

1. **Що буде, коли дія не вдасться?** Чи не повторюватиметься вона щокадру чи щосекунди?
2. **Що буде при зміні власника об'єкта або перезапуску?** Чи не лишиться старий стан у ZDO, чи не загубиться потрібний?
3. **Чи показує вимірювач правду?** Перш ніж вірити теорії, перевір сам інструмент.
4. **Це причина чи симптом?** Якщо причини не знайдено, так і скажи.
5. **Чи не вимірюється один раз те, що рухається?** Могила, щогла, голова, сидіння.
6. **Скільки це коштує?** Як часто спрацює і скільки об'єктів обійде, коли в грі 10 NPC і 5 гравців.
7. **Чи бачили це в грі?** Якщо ні, додай у `docs/UNTESTED.md` і не кажи, що воно працює.
8. **Змінив, як щось викликається (реєстр, поділ, перейменування)?** Знайди пошуком кожне місце старого виклику й пройди один справжній рядок даних від читання до виконання. Переводячи кроки сцен на дієслова, я лишив старий пошук у `StoryScenes.Begin`: `player`, `bird`, `npc` не запускались би, а збірка й усі перевірки були зелені.
9. **Зелена збірка не каже, що працює.** Компілятор і перевірки звіряють слова, а не поведінку. У звіті так і пиши: «зібрано, у грі не бачено». Чого не перевірено, того не обіцяй у теперішньому часі.
10. **Кого ще це зачепило?** Пройди цей список: людина сюжету й поселенець (`NpcDef.Settler`); деталь місця сюжету, прихована чи замкнена (`NpcBase`, `LocState.Absent`); другий гравець, що стоїть на тому ж етапі; окремий сервер без гравця; старий світ і новий; перезахід посеред дії. Замок на кліку гравця людей не зупиняє: вони йдуть повз `Interact`.
11. **Велика переробка?** Перед тим як показати її користувачу, дай незалежно прочитати код тому, хто не бачив моїх висновків: окремо ядро, окремо дані рядок за рядком, окремо стики з іншими системами. Сам я свого пропуску не бачу.
12. **Масова правка скриптом?** Скрипт пишеться у файл, а не в командний рядок (зворотні скісні й лапки там ламаються мовчки), і падає, якщо рядок не знайдено чи знайдено двічі. Після нього звір, скільки змінилось: «files 0» теж виглядає як успіх.
13. **⚠️ Виправив вид помилки чи один випадок?** Перед новим кодом пошукай, чи ядро вже це робить (шукай саму дію, а не лише назву: `transform.position =`, `Time.deltaTime`, своє ковзання). Знайшов помилку — знайди пошуком КОЖНЕ місце з тією самою помилкою й виправ їх усі через одне місце ядра в тій самій правці, а тоді закрий цей вид правилом у `arch_check`/`storycheck`. Виняток у правилі для тих самих файлів — це дірка, через яку помилка й пройшла. 2026-11-06 ривки сідання виправили в одній функції (`NpcBody.Glide`), а того ж дня сходинка отримала своє ковзання поруч, старим способом; ще чотири місця рухали тіло самі, а правило `body-put` мало винятки саме для них. Наступного дня ядро довелося «переписувати знову».

## Як писати сюжет (дані)

Кожен рядок узятий із помилки в пролозі. `storycheck` бачить слова, а не задум, тож це читай сам.

**Етап**
- Порядок: на вході `start:`, потім `fork`; далі кожні пів секунди `fork`, потім `wait`/`on`/`scene`. Тож `start:` виконується і тоді, коли розвилка одразу веде геть: наказ у ньому (`npc X follow`) лишиться. Етап, куди приходять із такого, спершу знімає його: `start: npc X free; npc X hold …`.
- Чекай факт, а не подію: `wait: flag x` переживе перезахід, `on: подія` живе один прохід. `on:` лише там, де факту нема.
- Подія може статись поза етапом (лист поза прологом, серце на іншому етапі): `fork` самого квесту спрацьовує на кожному етапі (`fork: world heart_first -> lantern`).
- `saga:` лише в особистому квесті й на етапі, через який проходять усі, хто це зробив; подія сервера йде в Сагу через `tales`.
- Один факт — один ключ. Якщо модуль уже ставить слово (`heart_first`), сюжет питає його, а не заводить своє.

**Двоє гравців**
- Квест сервера (`owner: server`) сам тримає один етап на світ: прапорець «це зробив я» не потрібен. Розвилка, поки грає сцена цього етапу, чекає її кінця (і в особистому квесті). Дія такого квесту виконується на одній грі, тож вона пише лише у світ, а не в персонажа.
- Особистий квест: кожен грає свій. Сцена, чию людину тримає сцена іншого гравця, чекає й грається потім.

**Сцена**
- `do`, `drop`, `door`, `own` роблять сцену зіграною з цієї миті: удар чи перезахід далі доробить решту мовчки й сцена пройде. Тож їх ставимо якомога пізніше: знайомство, що обірвалось після `do` на другому кроці, гравець більше не побачить.
- `bird come` чекає, поки птах сяде; щоб одразу кружляв — `nowait`.
- Слово кроку з місцем: запис сам каже, де воно (`PlaceAt`). Умова в `if`, `until`, `needs` — будь-яка; правило сервера (`becomes`, `follows`, `cold`, `fog`, `live … when`, `after`) — лише умови світу.

**Місце й річ**
- Річ, що зникає для гравця: `hidewhile` і `touch` на ті самі умови, інакше іскри висять у повітрі.
- На етапі, де дотик уже почав сцену й вона ще чекає, `touch` гасне (`!step … heart_talk`): другий E не має зробити `elsedo`.
- Що в стані місця немає, людина не використає, але своя точка автора (`spot:`, `bed`) повинна мати сенс у кожному стані, де вона діє: табір зник — `live … when` переводить людину; між цим є проміжок, поки ніхто не бачить.

**Люди сюжету**
- Шаблон без розмови `common` — не поселенець. Нова поведінка для «усіх мешканців» спершу питає `Settler`. Команди (`hold`, `live`) зберігаються за id шаблону, не за тегом.

## Перевірка

- **`rw_build` сам запускає** `tools/arch_check.js` (ці правила), `tools/storycheck.js` (стадії, сцени, місця, люди, вигляди в `assets/story` існують; слова кроків, умов, дій і рядків місць є в коді; код не називає квести, місця, людей сюжету), `tools/clipcheck.js` (кліпи й ті, що названі в сценах), `tools/patchcheck.ps1` (після компіляції: кожен патч Harmony знаходить свій метод саме на тому типі, що названий, бо інакше він нічого не робить, а гра пише лише рядок у лог) і перевірки фраз (`talkcheck`, `bookcheck`: ворони; `npcwordcheck`: люди, різноманіття й форми). Перевірка зупиняє збірку. Не обходь її. Дозвіл-виняток у ній додавай лише з явної згоди користувача.
- **Старий код не зупиняє збірку, але й рости не може.** `tools/arch_baseline.json` тримає для кожного файлу кількість: `catch`, що нічого не пише; збережених `user:id`; важких викликів; патчів без `PatchGuard`. Виправив старе: запусти `node tools/arch_check.js --tighten`, числа лише зменшуються. Нове проходить через ядро або з поясненням у своєму рядку: `// quiet:`, `// session:`, `// heavy:`. Пояснення має бути правдивим, це не виняток. Для патчів пояснення немає: лише `PatchGuard`. Піднімати числа, запускати `--new-baseline` і додавати винятки можна лише зі згоди користувача.
- **Перенести названу деталь у кресленні** (книга на столі хати, 2026-11-07): у вже збудованих світах деталь лишається на старому місці, ім'я на ній більше не лягає, і вона «німа» (не світиться, сцена на ній застрягає). Ядро на це має свій спосіб: одна назва може мати кілька рядків у `<місце>.names.txt` (так само шари в `.layers.txt`), будь-який знайдений годиться (`LocParts`). Переносиш деталь — **лиши старий рядок поруч із новим**, і старі світи знайдуть її на старому місці. `storycheck` пам'ятає кожен рядок назв і шарів, що йшов у збірку (`tools/names.seen.txt`, лежить разом із кодом; пише його лише `rw_build`). Якщо назву більше не знайти в межах 5 см, як шукає гра, він голосно попереджає (`STORY WARNING`). Прибрати рядок із `names.seen.txt` можна лише тоді, коли жоден світ не має старого місця. Тестовий світ можна й перебудувати (`<місце>.rebuild` у `config/RavenWatch/blueprints` з назвою світу).
- **Імена речей у місцях:** гра знаходить ім'я за префабом і місцем у межах 5 см; `storycheck` звіряє імена з кресленням; `touch:` без такого імені зупиняє збірку. У грі річ без деталі пише в лог (`LocTouch`).
- **Що перевірка не бачить:** чи код узагалі виконується (питання 8–9 вище), задум (другий менеджер своїми словами), частоту виклику, правдивість пояснення, ключі налаштувань у змінних, аргументи кроків і слова умов (їх перевіряє сама гра при завантаженні, у лог і у VERDICT перевірки сцени). Перші слова кроків сцени `storycheck` звіряє з кодом. Крок із власними словами після аргументу оголошує їх у своєму модулі, і `Read` бере їх звідти ж: `const string XStep = "prop take"`, `XFlags = { … }, XValued = { … }` (`StoryProps`). Тоді `storycheck` зупиняє одруківку в цих словах (і в людини: `npc <хто> prop take …`); предмет `RavenWatch_item_<id>` має бути в `assets/items` чи `assets/story/items`.
- **Самоперевірки в грі (лог):** рамка збудованого місця звіряється з його власними деталями раз на світ і після перебудови (`Loc.CheckFrame`, не на окремому сервері: «its frame fits its pieces» або «its frame is off … m»); кліп, лишений у `config/RavenWatch/player_anims` на машині автора, ніхто не читає, і лог це каже при старті; `take.js scene` перечитує сцени перед прогоном.
- **Неперевірене в грі:** `docs/UNTESTED.md`. Не будуй поверх цього так, ніби воно працює.
- **Окремо за потреби:** `tools/lint.js`, `phrasecheck.js`, `chaincheck.js` для фраз.
- **Цифри, а не враження:** `raven npc walk test 4`, `raven npc walk report`, `raven npc perf`, збій навмисно: `raven npc fail <хто> tick|mind|act|off`; чи NPC той самий після перезапуску, на іншій грі, після зміни господаря: `raven npc self` (порівнює з минулим записом цього світу); чому людина пішла туди: `raven npc why <хто>`; розмова без вікна: `raven npc talk <хто>`, усі теми фраз: `raven npc words <хто>` (у лог); порівнюй «до» і «після». Студія (`studio/request.txt`) дає знімки гри без рук.
- **Кілька чатів працюють з тим самим кодом одночасно.** Перед збиранням і встановленням перевір, чи не працює інший чат. Великі перейменування узгоджуй із ним.

## Відомий борг

- **Збережені `user:id` у коді воронів** (`HomeGuard`, `HomeLife`, `Outing`, `BeastPlay`, `SitOn`, `Perches`, `BloodRevenge`, `Diary`): частина може рватися після перезапуску, частина лише на сесію. `NpcKit` поки існує лише у збірці з NPC, тому для воронів його треба винести в спільне ядро.
- **`catch` без запису (273) і важкі виклики (379):** числа в `tools/arch_baseline.json`. Не всі вони помилки: перевіряй під час роботи з файлом, а не масовим проходом.
